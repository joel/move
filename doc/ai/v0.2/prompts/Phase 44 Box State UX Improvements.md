## Goal

Let a user advance **all** boxes through a major lifecycle step in one click —
"Seal all packing boxes", "Send all sealed boxes in transit", "Start unpacking
all", "Mark all unpacked" — instead of opening each box and transitioning it
individually. Reached from the Menu (an editor-only surface).

By the end: a "Bulk box steps" page shows the current state distribution and, for
each forward step that has boxes waiting, a confirm-guarded button that transitions
every box in that source state, reporting what moved and what was skipped (e.g.
roomless boxes can't be sealed).

## Why

Transitioning boxes one-by-one is tedious when the move reaches a milestone (the
truck arrives → seal everything; you're at the destination → start unpacking
everything). There's no batch path today — only per-box `BoxesController#transition`
and the unpacking checklist.

## Non-negotiable constraint (standing user directive)

**Never compute in Ruby what the DB can do** (AGENTS.md §1 #5, `Move/DatabaseAggregation`):
- State distribution counts → **`move.boxes.group(:status).count`** (one SQL query),
  never `pluck(:status).tally` / `.map`.
- The source-state set → **`move.boxes.where(status: from)`** (SQL filter). Iterating
  those records to transition each is *not* the anti-pattern (we act on each row);
  the cap/counts/filtering are SQL.

## Depends on

- Current `main` (v0.42.1). No other phase blocks this.

## Out of scope (YAGNI)

- **Backward bulk** (bulk unseal / bulk reopen) — those are corrective, per-box.
  This phase is the forward progression only.
- **Selecting a subset** of boxes — "all boxes in this state" only. Per-box checkbox
  selection is a separate, larger feature.
- **Async/progress bar** — transitions are cheap DB updates; do it synchronously (see
  Design #4). Note a background-job fallback if profiling shows large moves are slow.
- Changing the per-box transition flow, the seal "describe before sealing" modal, or
  the unpacking checklist.

## Design decisions (institutional reasoning)

1. **Reuse `Boxes::TransitionStatus` per box — don't hand-roll the UPDATE.** Each box
   must still pass the seal-requires-room guard, run the unpacked→items cascade, and
   emit `box.status_changed`. A new `Boxes::BulkTransition` loops the source-state
   boxes through the existing action, so every invariant and event is preserved with
   zero duplication.

2. **Forward steps only, derived as a curated list.** The "major steps" are the
   forward edges of `Box::TRANSITIONS`:
   | from | to | label |
   |---|---|---|
   | packing | sealed | Seal all packing boxes |
   | sealed | in_transit | Send all sealed boxes in transit |
   | in_transit | unpacking | Start unpacking all boxes |
   | unpacking | unpacked | Mark all boxes unpacked |
   Encode as `Boxes::BulkTransition::STEPS` (ordered `{from:, to:}`). A requested `to`
   not in this list → `Failure(:invalid_step)`. (Backward edges like `sealed→packing`
   are intentionally excluded.)

3. **Best-effort partial, not all-or-nothing.** Seal can't apply to a roomless box
   (`TransitionStatus` returns `:room_required`). The bulk transitions every box it
   can and **reports the skipped ones with reasons** — failing all 12 because 2 lack a
   room is the opposite of the convenience goal. Each per-box transition is itself
   atomic; the bulk is not wrapped in one big transaction.

4. **Synchronous (no job/progress).** A status transition is a cheap DB update; even a
   large move is a bounded set of fast UPDATEs, and the only fan-out (activity rows) is
   already bounded sync inserts (box status doesn't touch search). KISS + this is a
   deliberate "settings" action behind a confirm. (If a pathologically large move ever
   makes it slow, lift it to the label-print background-job pattern, #303 — noted, not
   built.)

5. **Activity feed: N per-box entries (reuse trade-off).** Reusing `TransitionStatus`
   emits one `box.status_changed` per box → the feed gets N "box sealed" rows. This is
   an accurate audit and the DRY choice. The alternative (one "Sealed 12 boxes" summary
   entry) would require bypassing the per-box event emission and is **out of scope** —
   flagged as a possible follow-up (group same-action same-second entries in the feed).
   *(Decision to confirm with product — see the question at hand.)*

6. **Surface = a dedicated page reached from the Menu**, editor-only. The Menu hub is
   link-rows; a dedicated `BoxStepsController#show` page has room for the state
   distribution + a confirm-guarded button per available step, and keeps the hub tidy.

## Implementation blueprint

### A. Action — `app/actions/boxes/bulk_transition.rb`
```ruby
module Boxes
  class BulkTransition < BaseAction
    STEPS = [
      { from: "packing",    to: "sealed" },
      { from: "sealed",     to: "in_transit" },
      { from: "in_transit", to: "unpacking" },
      { from: "unpacking",  to: "unpacked" }
    ].freeze
    TARGETS = STEPS.map { |s| s[:to] }.freeze
    SOURCE_FOR = STEPS.to_h { |s| [s[:to], s[:from]] }.freeze

    Result = Struct.new(:to, :transitioned, :skipped, keyword_init: true)

    def call(move:, to:, actor:)
      yield ensure_writable(move)
      to = to.to_s
      return Failure(:invalid_step) unless TARGETS.include?(to)

      # SQL-scoped to the source state; iterate to transition each (per-box guards
      # + unpacked cascade + box.status_changed event all preserved).
      results = move.boxes.where(status: SOURCE_FOR.fetch(to)).order(Arel.sql("number::bigint")).map do |box|
        [box, Boxes::TransitionStatus.new.call(box: box, to: to, actor: actor)]
      end
      transitioned = results.count { |(_, r)| r.success? }
      skipped = results.reject { |(_, r)| r.success? }
                       .map { |(box, r)| { number: box.number, reason: r.failure } }
      Success(Result.new(to: to, transitioned: transitioned, skipped: skipped))
    end
  end
end
```
*Emit an optional `boxes.bulk_transitioned` analytics event only if it doesn't also
create a duplicate feed entry — default: skip it (the per-box events are the record).*

### B. Routes + controller
```ruby
# under resources :moves do … end
get  "box_steps", to: "box_steps#show",   as: :box_steps
post "box_steps", to: "box_steps#create"
```
- **`BoxStepsController < MoveScopedController`** (`Current.nav_section = :menu`):
  - `show` → `authorize! @move, to: :edit_contents?, with: MovePolicy`; render
    `Views::BoxSteps::Show.new(move:, counts: state_counts, steps: available_steps)`.
  - `create` → `BulkTransition.new.call(move: @move, to: params[:to], actor: current_user)`;
    pattern-match `Success(result)` → redirect to `box_steps` with a summary flash;
    `Failure(:invalid_step)` → redirect with alert; `Failure(:move_archived)` →
    `read_only_redirect_path`.
  - `state_counts` = `@move.boxes.group(:status).count` (SQL). `available_steps` =
    `BulkTransition::STEPS.select { |s| counts.fetch(s[:from], 0).positive? }`.
- Editor-only: viewers/archived get the friendly redirect (mirror an editor surface);
  the Menu link is hidden for non-editors.

### C. View — `app/views/box_steps/show.rb`
- A SectionHeader + a **state distribution** strip (count per status, from `counts`).
- For each available step, a card: "Seal all **N** packing boxes" with a `button_to`
  POST to `move_box_steps_path(@move)` `params: { to: step[:to] }`, carrying
  `data: { turbo_confirm: confirm_copy(step, n) }`. The `unpacked` step's confirm warns
  the cascade removes items from their boxes.
- Empty state when no step has boxes ("Every box is already unpacked / nothing to advance").

### D. Menu link — `app/views/menu/show.rb` + `MenuController`
Add an editor-only Organize link "Bulk box steps" → `move_box_steps_path`. Pass an
`editor:` flag from `MenuController` (`allowed_to?(:edit_contents?, @move, with: MovePolicy)`)
the way `admin:` already gates member management.

### E. i18n — `config/locales/box_steps.en.yml` (new)
Title/subtitle, per-step button labels (`seal_all`, `send_in_transit`, `start_unpacking`,
`mark_unpacked` with `%{count}`), confirm strings (unpacked one mentions item removal),
the summary flash (`transitioned`, `skipped` with numbers + reason), empty state. Plus
`menu.show.box_steps`.

## Events

## Tests

- **`BulkTransition`**: seals all `packing` → `sealed`; a roomless packing box is
  **skipped** with `:room_required` and reported (others still sealed); only the
  source-state boxes change (a `sealed` box untouched during a "seal" step);
  `unpacking → unpacked` cascades in-box items to `removed`; archived move →
  `Failure(:move_archived)`; unknown `to` → `Failure(:invalid_step)`; emits a
  `box.status_changed` per transitioned box (an Activity row each).
- **State counts** come from SQL (`group(:status).count`) — assert correctness, and
  that the page offers a step only when its source state is non-empty.
- **Request**: `show` renders counts + the right step buttons for an editor; a viewer
  is redirected/forbidden; `create` transitions + redirects with the summary flash;
  archived move → read-only redirect, no transition.
- **Menu**: an editor sees the "Bulk box steps" link; a viewer does not.
- **System (rack_test)**: Menu → Bulk box steps → "Seal all" → counts update + flash;
  the `turbo_confirm` is present on each button.

## Acceptance criteria

- Each forward lifecycle step can be applied to all boxes in its source state in one
  click, behind a confirm.
- Roomless boxes are skipped on seal and clearly reported; the unpacked cascade still
  removes items.
- All counts/filtering are SQL; `Move/DatabaseAggregation` passes. No schema change.
- Editor-only; archived moves are read-only. All gates green.

## Gotchas / risks (read before coding)

1. **Reuse `TransitionStatus`, don't duplicate** — or the seal-room guard and the
   unpacked→items cascade drift. The bulk action is a thin loop + a result summary.
2. **Seal partial-failure is expected** (`:room_required`) — surface skipped box
   numbers, don't fail the batch.
3. **N activity entries** from the per-box events (Design #5) — confirm this is
   acceptable vs a single summary entry before building the alternative.
4. **DB aggregation** — `group(:status).count`, `where(status:)`; never `pluck.tally`.
5. **`turbo_confirm` + a non-GET `button_to`** — fine in the app; live-verify the
   dialog fires (agent-browser doesn't auto-accept `confirm()` — patch
   `window.confirm = () => true` before clicking, per AGENTS.md §5).
6. **Editor gating in two places** — the Menu link (hide for non-editors) *and* the
   controller (`edit_contents?`), so there's no dead-end 403 and no bypass.
7. **Concurrent state drift** — the action re-queries `where(status: from)` at submit
   time, so a box that already left the source state is simply not included (no stale
   double-transition).
8. **`:js` realtime not involved** — this is a PRG redirect, no cable; the page is
   re-rendered with fresh counts. (No chromedriver dependency for the core flow.)
