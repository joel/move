## Goal

Make bulk label-print generation feel responsive: instead of a synchronous request
that blocks while a large PDF renders, generate the PDF in a **background job** that
reports **live progress** over ActionCable/Turbo Streams (exactly like the
semantic-search re-embedding bar, #239), then hand the user a **Download** when it's
ready. No spinner-in-the-dark; the user watches "Generating 37 of 200 labels…".

By the end: submitting the range form creates a tracked `LabelPrintRun`, redirects to
a progress page whose bar advances live, and resolves to a "Your labels are ready —
Download" state — all without polling, and without ever tying up a Puma worker on a
1000-page Prawn render (which would also blow the Cloudflare/proxy request timeout).

## Why (problem statement)

- `LabelPrintsController#print` builds `BoxLabelsPdf` **synchronously in the request**
  and `send_data`s it inline. For a large range (up to `MAX_LABELS = 200` boxes ×
  2 pages = 400 pages) this is slow, gives zero feedback, and risks a request timeout
  behind Cloudflare/kamal-proxy.
- We already have a proven, no-polling progress pattern: the re-embedding bar (#239) —
  `IndexingRun` + atomic SQL progress increments + `Turbo::StreamsChannel.broadcast_replace_to`
  + a purely-presentational status component + `turbo_stream_from`. Mirror it.

## Non-negotiable constraint (user directive, "written in stone")

**Never compute in Ruby what the database can do. Let the DB do the lifting — loading
rows to count/min/max/filter in the app layer is junior-level and is forbidden.** This
is AGENTS.md §1 #5 and is enforced by the `Move/DatabaseAggregation` cop. Concretely in
this phase:

- `total_count` (boxes in range) → **`scope.count`** (SQL `COUNT`), never `.to_a.size`
  / `pluck(...).size`.
- range bounds/defaults → **`pick(Arel.sql("MIN(number::bigint), MAX(...), COUNT(*)"))`**
  with `&.to_i` coercion (the existing `range_bounds`; `number` is a *string* column,
  so Arel.sql aggregates return strings and **must** be coerced — the #283 lexical bug).
- progress increment → **atomic `update_all("completed_count = completed_count + N …")`**,
  never load-modify-save.
- box selection/order → **`where("number::bigint BETWEEN ? AND ?").ordered`** in SQL.
- `progress_percent` is arithmetic on *two scalar columns of one already-loaded row* —
  this is the documented **exception** (not a row aggregation), fine; mirror
  `IndexingRun#progress_percent`. Call it out so review doesn't false-flag it.

## Out of scope (YAGNI)

- Parallelising PDF generation (Prawn builds one document sequentially — one job).
- Per-box failure/retry semantics (a Prawn error aborts the whole PDF → the run fails
  as a unit, with a "try again").
- Changing the single-box label endpoint (`LabelsController#show` — 2 pages, instant,
  stays synchronous inline).
- Email/share-link delivery of the PDF.
- Auto-download-on-complete via JS is an **optional** enhancement (see §UI note), not
  the core deliverable.

## Design decisions (institutional reasoning)

1. **Always async, even for small ranges.** One code path; and a synchronous
   multi-hundred-page Prawn render in a web request is a real reliability hazard
   (request timeout behind Cloudflare/kamal-proxy, Puma worker tied up). For a tiny
   range the job finishes in <1s and the bar flashes to 100% → Download. (Threshold
   "sync if small" was considered and rejected: two code paths, and the timeout risk
   is the real driver, not just UX.)

2. **One job builds the whole PDF, reporting progress per box.** A PDF is a single
   sequential document — you can't fan it out across jobs (unlike #239's per-item
   embeds). So progress is recorded *inside* the build loop: `BoxLabelsPdf#render`
   gains an optional block yielded once per box; the job's callback calls
   `LabelPrintRuns::RecordProgress` (atomic increment + **throttled** broadcast).

3. **The finished PDF is an Active Storage attachment on the run.** `LabelPrintRun
   has_one_attached :document`. The Download endpoint serves that blob. (Same storage
   stack as everything else; reuses the proxy/`send_data` path.) Old run PDFs are
   reaped by a daily tenant-aware cleanup (mirror `PurgeAbandonedUploadsJob`).

4. **No request host in a job → pass it in.** The QR on each label encodes
   `move_scan_resolve_url(move, token)`, which today uses the **request host**. A job
   has no request, so the controller passes `host:` + `protocol:` (from `request`) to
   the job, which builds URLs via
   `Rails.application.routes.url_helpers.move_scan_resolve_url(move, token, host:, protocol:)`.
   This preserves current behaviour exactly. (Canonical alternative —
   `"#{Apartment::Tenant.current}.#{Rails.application.config.x.tenant_zone}"`, as
   `rodauth_main.rb:245` builds it — is noted but not used, to avoid a dev/prod host
   divergence from today's code.)

5. **Per-run signed stream is the auth boundary** (AGENTS.md §1 #4). Subscribe with
   `turbo_stream_from(@run, :progress)`; broadcast with
   `broadcast_replace_to(@run, :progress, target: Components::Ui::LabelPrintStatus::ID, …)`.
   The run uuid is tenant-unique; no per-user channel auth needed. The broadcast is
   wrapped in `rescue` (a broadcast must never fail the job) with a
   `# rubocop:disable Move/BroadRescue` + reason.

6. **POST→redirect→GET (PRG).** Form `POST`s to create a run, then **redirects** to the
   run show page (HTML). Because the response is now an HTML redirect (not a PDF), the
   form **drops `data-turbo="false"`** that the current form needs (the old
   "Turbo swallows a 200 PDF" workaround, see `spec/system/label_print_spec.rb`). The
   Download endpoint still returns a PDF, but it's reached by a plain link/navigation,
   not a Turbo form submit, so no workaround is needed.

7. **Throttle broadcasts, not counts.** Increment `completed_count` every box (cheap
   atomic SQL), but broadcast at most ~20 times over the run (every
   `[total/20, 1].max` boxes) plus a guaranteed final broadcast — avoids up-to-200
   component re-renders/pushes while keeping the bar smooth.

## Implementation blueprint

### A. Migration — `label_print_runs` (tenant table)
```ruby
create_table :label_print_runs, id: :uuid do |t|
  t.references :move, type: :uuid, null: false, foreign_key: true
  t.bigint  :from_number, null: false
  t.bigint  :to_number,   null: false
  t.integer :total_count,     null: false, default: 0
  t.integer :completed_count, null: false, default: 0
  t.string  :status, null: false, default: "queued"
  t.datetime :started_at
  t.datetime :finished_at
  t.timestamps
end
```
Runs per tenant via the deploy entrypoint (`db:prepare && db:migrate`); commit
`db/structure.sql`.

### B. Model — `app/models/label_print_run.rb` (mirror IndexingRun)
```ruby
class LabelPrintRun < ApplicationRecord
  STATUSES = %w[queued processing completed failed].freeze
  ACTIVE   = %w[queued processing].freeze
  belongs_to :move
  has_one_attached :document            # the finished PDF
  validates :status, inclusion: { in: STATUSES }
  scope :active, -> { where(status: ACTIVE) }
  def in_progress? = ACTIVE.include?(status)
  def ready?       = status == "completed" && document.attached?
  def progress_percent                  # scalar derivation on one row — allowed
    return 0 if total_count.zero?
    ((completed_count.to_f / total_count) * 100).clamp(0, 100).round
  end
end
```

### C. Actions — `app/actions/label_print_runs/`
- **`Start`** — `call(move:, from:, to:, host:, protocol:)`:
  - validate: `from`/`to` present and `from <= to` → else `Failure(:invalid_range)`.
  - `count = boxes_in_range(move, from, to).count` (SQL). `Failure(:empty)` if 0;
    `Failure(:too_many)` if `> LabelPrintsController::MAX_LABELS` (move the constant to
    the model or a shared place).
  - `run = move.label_print_runs.create!(from_number: from, to_number: to,
    total_count: count, status: "queued", started_at: Time.current)`.
  - `LabelPrintRuns::GenerateJob.perform_later(run.id, tenant: Apartment::Tenant.current,
    host:, protocol:)`; `run.update!(status: "processing")`.
  - `broadcast_status(run)` (initial 0%); `Success(run)`.
  - *(Read-intent: not gated by `ensure_writable` — generating labels for an archived
    Move is allowed, like viewing a label; it persists only a transient run, no domain
    mutation. State this in the action doc.)*
- **`RecordProgress`** — `call(run_id:, by: 1)`: atomic
  `LabelPrintRun.where(id:, status: ACTIVE).update_all("completed_count = completed_count + #{by.to_i}, status='processing', updated_at = NOW()")`
  then `broadcast_status` (caller throttles). Mirror `IndexingRuns::RecordProgress`'s
  literal-SQL discipline.
- **`Finalize`** — attach the rendered PDF, set `completed`/`failed`, final broadcast
  (or fold into the job).
- **`Broadcasting`** (module) — `broadcast_status(run)`:
  ```ruby
  Turbo::StreamsChannel.broadcast_replace_to(
    run, :progress,
    target: Components::Ui::LabelPrintStatus::ID,
    html: ApplicationController.render(Components::Ui::LabelPrintStatus.new(run: run), layout: false))
  rescue StandardError => e # rubocop:disable Move/BroadRescue -- §1#4 broadcast must not break emitter
    Rails.logger.warn("[label_print] status broadcast failed: #{e.class}: #{e.message}")
  ```

### D. Job — `app/jobs/label_print_runs/generate_job.rb`
```ruby
def perform(run_id, tenant:, host:, protocol:)
  Apartment::Tenant.switch(tenant) do
    Current.tenant = tenant
    run = LabelPrintRun.find_by(id: run_id)
    return unless run&.in_progress?
    begin
      boxes = boxes_in_range(run.move, run.from_number, run.to_number).includes(:room)
      entries = boxes.map { |b| { box: b, scan_url: scan_url(run.move, b, host, protocol) } }
      step = [run.total_count / 20, 1].max
      pdf = BoxLabelsPdf.new(entries: entries).render do |done, _total|
        LabelPrintRuns::RecordProgress.new.call(run_id: run.id, by: 1) if (done % step).zero?
      end
      run.document.attach(io: StringIO.new(pdf), filename: filename(run),
                          content_type: "application/pdf")
      run.update!(status: "completed", completed_count: run.total_count, finished_at: Time.current)
      LabelPrintRuns::Broadcasting.broadcast_status(run)   # final "ready"
    rescue StandardError # rubocop:disable Move/BroadRescue -- tag failed + re-raise (no swallow)
      run.update!(status: "failed", finished_at: Time.current)
      LabelPrintRuns::Broadcasting.broadcast_status(run)
      raise   # Solid Queue records it; a retry no-ops (run no longer in_progress)
    end
  end
end

def scan_url(move, box, host, protocol)
  Rails.application.routes.url_helpers.move_scan_resolve_url(move, box.qr_token, host:, protocol:)
end
```
*(`boxes_in_range` is the existing SQL scope — extract to a shared concern/model scope
so the controller, action, and job share it.)*

### E. `BoxLabelsPdf#render` — add a per-box progress block
```ruby
def render
  doc = Prawn::Document.new(...); register_unicode_font(doc)
  first = true
  @entries.each_with_index do |entry, i|
    PAGE_COUNT.times { doc.start_new_page unless first; first = false; label_content(...) }
    yield(i + 1, @entries.size) if block_given?     # report after each box's pages
  end
  doc.render
end
```
Backward-compatible: `BoxLabelPdf` (single box) calls `render` with no block.

## Gotchas / risks (read before coding)

1. **No request host in jobs** — pass `host:`/`protocol:` from the controller; build scan
   URLs with `url_helpers.move_scan_resolve_url(move, token, host:, protocol:)`. Forgetting
   this yields `missing host` errors or `example.com` URLs.
2. **Drop `data-turbo="false"`** on the range form — the response is now an HTML redirect,
   not a PDF. (The old workaround was the "Turbo swallows a 200 PDF" gotcha; the new
   download is a plain navigation, not a Turbo form.)
3. **Broadcast must not break the job** — wrap `broadcast_replace_to` in `rescue` with a
   `Move/BroadRescue` disable + reason (§1 #4).
4. **Signed stream from the run** (`turbo_stream_from(@run, :progress)`) — the run uuid is
   the auth boundary; the broadcast target id must match the component's stable `ID`.
5. **DB aggregation only** — `count`/`pick(MIN/MAX)`/`update_all` increment; never load
   rows to count. Coerce Arel.sql aggregates with `&.to_i` (#283 lexical-string bug).
6. **Job tenant restore** — `Apartment::Tenant.switch(tenant)` + `Current.tenant`; jobs
   never inherit the request tenant. Pass `tenant: Apartment::Tenant.current` at enqueue.
7. **Retention** — completed-run PDFs accumulate in storage; the daily purge is part of
   the deliverable, and it must be **tenant-aware** (runs live in tenant schemas).
8. **`:js` progress spec needs real Chrome (CI-only)** — the dev container lacks
   chromedriver; assert realtime behaviour via `/product-review`, not a local `:js` run
   (execution-plan Step 6).
9. **Optional auto-download Stimulus controller** (connect → navigate to the download) is
   stale in dev until `assets:precompile` + `bin/cli app restart` (importmap gotcha) — if
   added, account for it; otherwise a Download button is enough.
10. **`MAX_LABELS` guard stays** — reject `too_many` *before* creating a run.
11. **Prawn Unicode font** — `BoxLabelsPdf` already registers Noto via `PdfFonts`; the
    job path inherits it (no AFM-font crash on accented room names). Keep the Unicode
    render spec.
