> **Status: IMPLEMENTED** (issue #310, branch `feature/labels-per-box`) —

> `BoxLabelsPdf` `copies:`. See `doc/project/architecture.md` §4a.

## Goal

Let a user choose **how many copies of each box's exterior label** get printed,
per Move, instead of the current hard-coded **2** (lid + side). Set it once in
**Settings → Move Preferences** ("Labels per box": 1–10, default **2**), and have
it apply to **both** print paths:
- the **bulk** label-print PDF (Menu → Print Labels, #303), and
- the **single-box** label PDF (`boxes/:id/label`).

By the end: a Move admin/editor picks "Labels per box" in Settings; every label
print for that Move then emits that many identical label pages per box. The
default (2) preserves today's behaviour exactly.

## Why

Different printers/workflows want a different number of copies: some users stick
one label on the lid + one on a side (today's fixed 2), some want a single label,
some want 3–5 (lid, two sides, top-of-stack). Today the count is the frozen
constant `BoxLabelsPdf::PAGE_COUNT = 2` — there is no way to change it without a
code edit. This is a per-Move preference, exactly like `unit_system` and
`auto_confirm_threshold`.

## Non-negotiable constraints (standing user directives)

- **Default MUST be 2.** The column default and the PDF `copies` default both stay
  `2` so every existing label print is byte-for-byte unchanged. A different default
  would silently alter all current prints.
- **Never compute in Ruby what the DB can do** (AGENTS.md §1 #5). There is no
  aggregation here, but keep the box-count snapshot/cap in SQL (already the case in
  `LabelPrintRuns::Start`); do not load rows to count.
- **Live-test auth + the print flow** after the change (AGENTS.md §5).
- **`schema_format :sql`:** after the migration, `bin/rails db:migrate` then commit
  the regenerated `db/structure.sql` (the `RailsSchemaUpToDate` overcommit hook).

## Depends on

- Current `main` (v0.43.0). Builds directly on the Phase 43 label-print machinery
  (#303/#304) and the F3 Settings surface (D13). No other phase blocks this.

## Out of scope (YAGNI)

- **Per-box override** of the count (e.g. "box 7 prints 5"). This is a Move-level
  preference only.
- **Different front/back layouts** per copy — every copy is the identical label
  (unchanged from today's lid+side).
- **A page cap separate from the box cap.** `LabelPrintRun::MAX_LABELS = 200` stays
  a **box-count** cap; `labels_per_box` is bounded 1–10 by validation, so worst case
  is 200×10 = 2000 pages on an explicitly-chosen large job. (If product later wants a
  hard page cap, switch the `Start` guard to `box_ids.size * copies > MAX_LABELS` —
  noted, not built.)
- **Logidze field-history / activity-feed revert for this setting.** `unit_system`
  and `auto_confirm_threshold` are Logidze-tracked; `labels_per_box` is a print
  preference with no audit value, and tracking it needs a trigger-recreate +
  re-snapshot migration. Explicitly deferred (see Design #5).
- Changing the label **layout** (62×90mm, QR hero, number/room/token) or the bulk
  print form/range UX.

## Design decisions (institutional reasoning)

1. **A new `moves.labels_per_box` integer column, default 2.** Mirrors
   `auto_confirm_threshold` exactly: a plain per-Move scalar preference. Default 2
   reproduces today's `PAGE_COUNT = 2`. Bounded **1..10** (`Move::LABELS_PER_BOX_RANGE`)
   — generous (the user named "1, 2, maybe 5") but bounds the worst-case page count.

2. **Parametrise `BoxLabelsPdf` with `copies:` (default 2), don't read the Move in
   the builder.** The PDF builder stays pure/host-agnostic (it already takes
   pre-built `entries`). Replace the `PAGE_COUNT.times` loop with `copies.times`,
   where `copies` is an initializer arg defaulting to `DEFAULT_COPIES = 2` (so the
   builder is still usable without a Move and all existing `.new(entries:)` callers
   are unchanged). `BoxLabelPdf` forwards `copies:`.

3. **Snapshot `copies` at `Start`, pass it as a job argument.** Consistent with how
   #303 snapshots `box_ids` (and host/protocol): the bulk job renders the count the
   user had **when they clicked**, so a Settings change while the job is queued can't
   retroactively change the in-flight PDF. `Start` reads `move.labels_per_box` and
   passes `copies:` to `GenerateJob.perform_later`; the **single-box** path is
   synchronous so it just reads `@move.labels_per_box` inline. **No new column on
   `label_print_runs`** — `total_count` stays the box count; pages = boxes × copies;
   the per-box progress yield is unchanged.

4. **Settings control = an auto-submitting `<select>` 1–10.** A segmented toggle
   (like units) doesn't scale to 10 options; a slider (like threshold) is wrong for a
   small discrete count. Use `Components::Ui::Select` inside a `form_with(data:
   { controller: "auto-submit" })` with `select(data: { action:
   "change->auto-submit#submit" })` — the **existing** `auto_submit_controller.js`
   (no new asset, so no precompile-staleness gotcha). Editors see the select; viewers
   / archived Moves see the resolved number as a read-only chip (mirror `unit_toggle`).

5. **No Logidze tracking (deferred).** Adding `labels_per_box` to the
   `logidze_on_moves` trigger include-list (`{name, unit_system,
   auto_confirm_threshold}`) would make edits appear in the activity feed and be
   revertable — but it requires a trigger-recreate + `logidze_snapshot` re-run
   migration for a low-stakes print preference. The plain `add_column` does **not**
   touch the trigger (Logidze ignores columns outside its include-list), so this is a
   clean omission. Emit a `move.labels_per_box_changed` event for symmetry with the
   other setters (audit hook), but don't wire it to the feed.

6. **Cap stays a box cap.** `MAX_LABELS = 200` already bounds the bulk job; copies is
   validation-bounded to ≤10. Document the boxes×copies page worst-case in
   `architecture.md`; don't change the guard semantics (KISS, minimal blast radius).

### B. Model — `app/models/move.rb`
```ruby

# (lid + side) preserves the prior fixed BoxLabelsPdf::PAGE_COUNT behaviour.
LABELS_PER_BOX_RANGE = (1..10).freeze
# …
validates :labels_per_box,
          numericality: { only_integer: true,
                          greater_than_or_equal_to: LABELS_PER_BOX_RANGE.min,
                          less_than_or_equal_to: LABELS_PER_BOX_RANGE.max }
```

### C. Action — `app/actions/moves/set_labels_per_box.rb`
```ruby
module Moves
  class SetLabelsPerBox < BaseAction
    def call(move:, labels_per_box:, actor: nil)
      yield ensure_writable(move)
      value = yield coerce(labels_per_box)
      yield with_responsible(actor) { persist(move, value) }
      yield emit_event(move, actor, value)
      Success(move)
    end

    private

    def coerce(raw)
      value = Integer(raw)
      return Failure(:invalid_labels_per_box) unless Move::LABELS_PER_BOX_RANGE.cover?(value)

      Success(value)
    rescue ArgumentError, TypeError
      Failure(:invalid_labels_per_box)
    end

    def persist(move, value)
      move.update!(labels_per_box: value)
      Success(move)
    rescue ActiveRecord::RecordInvalid => e
      Failure(e.record.errors)
    end

    def emit_event(move, actor, value)
      Rails.event.notify(
        "move.labels_per_box_changed", move_id: move.id, actor_id: actor&.id, labels_per_box: value
      )
      Success()
    end
  end
end
```

## Data model

**One new column:** `moves.labels_per_box` integer, `NOT NULL DEFAULT 2`. No new
tables, no `label_print_runs` change (copies is a job argument, not persisted).

## Events

New `move.labels_per_box_changed` (audit symmetry with the other setters). No
subscriber wired by default (Design #5). Existing `box.*`/label-print events unchanged.

## Tests

- **`Moves::SetLabelsPerBox`**: sets a valid value (1, 5, 10); rejects `0`, `11`, and
  non-integer (`"x"`, `2.5`) with `Failure(:invalid_labels_per_box)` and no write;
  archived Move → `Failure(:move_archived)`; emits `move.labels_per_box_changed`.
- **Model**: validates 1..10 integer; rejects 0/11/non-integer; default is 2 on a new Move.
- **`BoxLabelsPdf`**: `copies: 3` over 4 boxes → `/Count 12`; default (no arg) → 2× (the
  existing `/Count 8` spec must still pass); single entry `copies: 1` → `/Count 1`.
- **`BoxLabelPdf`** / **`LabelsController` request**: a Move with `labels_per_box: 1`
  renders a 1-page single-box label (`/Count 1`); default Move → 2 pages (existing
  `labels_spec` stays green).
- **`LabelPrintRuns::Start`**: enqueues `GenerateJob` with `copies: move.labels_per_box`
  (assert the job args, e.g. `have_enqueued_job(...).with(hash_including(copies: 5))`).
- **`GenerateJob`**: renders boxes×copies pages for the run's Move's value (perform the
  job inline, assert the attached PDF's `/Count`).
- **Settings request**: editor PATCH updates `labels_per_box`; invalid value keeps the
  old one + alert; viewer → forbidden (no change); archived → read-only redirect (no
  change); GET shows the editable select for an editor and the resolved number for a
  viewer.
- **System (rack_test)**: Settings → change "Labels per box" to 3 (auto-submit) →
  flash + the select shows 3 selected on reload.

## Gotchas / risks (read before coding)

1. **Default MUST be 2** in both the column and `BoxLabelsPdf::DEFAULT_COPIES`, or every
   existing print silently changes. The existing `box_labels_pdf_spec` `/Count 8` and
   `labels_spec` "two pages" assertions are the regression tripwire — keep them green.
2. **`structure.sql`** must be re-dumped + committed (schema_format :sql; the
   `RailsSchemaUpToDate` hook blocks the commit otherwise).
3. **Snapshot `copies` into the job** (Design #3) — don't have `GenerateJob` re-read
   `run.move.labels_per_box`, or a Settings change mid-queue changes the in-flight PDF.
   Give `perform` a `copies:` default so jobs enqueued before the deploy still render 2.
4. **Phlex blocks inline `on*`** — use the existing `auto-submit` Stimulus controller
   for the select, never `onchange:` (raises `Phlex::ArgumentError`). No new JS asset →
   no precompile-staleness gotcha; but if the Select introduces a brand-new Tailwind
   utility, rebuild dev CSS (`tailwindcss:build`) — the Select component is already used
   elsewhere, so its classes should already be compiled.
5. **Page cap** — `MAX_LABELS` stays a box cap; boxes×copies pages (≤2000) is the
   explicit worst case. Don't silently re-interpret the cap.
6. **Editor gating in one place** — `write_setting` (edit_settings?) + the read-only
   note in the view; a viewer never sees the select (mirror `unit_toggle`).
7. **`Integer()` coercion** — the form sends a string; `Integer("3")` works, `Integer("3.5")`
   raises (good — rejected). Range-check before persisting so an out-of-range value is a
   clean `Failure`, not a model error round-trip.
