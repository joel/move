## Goal

Stop storing and serving full-resolution phone photos. At upload, downscale and
recompress every image to a bounded, high-quality **master** and store *that* (discarding
the multi-MB original). At display, serve right-sized **variants** per surface instead of
the master. Backfill existing media to reclaim storage.

By the end of this phase: a 12-megapixel phone capture (~3–5 MB) is stored as a ~300–600 KB
JPEG master (long edge ≤ 2048 px), the box gallery grid loads ~400 px thumbnails instead of
the full image, recognition is unaffected, and a re-runnable task has optimised every
pre-existing photo across all tenants.

## Why (problem statement)

- `ImageNormalizer` passes **native** JPEG/PNG/WEBP through **unchanged** today
  (`app/services/image_normalizer.rb` — `return @attachable if NATIVE.include?(type)`), so
  the original phone resolution is what gets stored.
- All **5 display surfaces** serve the original blob directly to `<img>` via
  `view_context.rails_storage_proxy_path(media.image)` — no variants — so desktop downloads
  the full image even for a small grid tile. (Confirmed in code; the `ImageNormalizer`
  class comment even states "the 5 display surfaces serve the original blob directly".)
- Recognition does **not** need the original: `RecognitionProviders::Base#encoded_image`
  already downscales its own copy to `MAX_IMAGE_EDGE = 1536` for the vision call
  (`app/services/recognition_providers/base.rb:241`). So shrinking the stored master to
  2048 px costs recognition nothing.

## Depends on

- Current `main` (all D0–D13 shipped). No other phase blocks this.
- libvips present (it is, in the app image + CI) — required for variants and the optimiser.

## Out of scope (YAGNI — do not build)

- Responsive `srcset`/multi-density `<picture>` sources (single variant per surface for now).
- WebP/AVIF *output* negotiation (keep JPEG masters/variants; revisit later).
- Cloudflare/CDN image resizing.
- Video or non-image media.
- Pre-warming variants in a background job (lazy generation is fine).
- Any change to the 25 MB upload input cap or to recognition's own 1536 px downscale.

## Design decisions (the institutional reasoning)

1. **One choke point — extend `ImageNormalizer`.** Both the web multipart path and the MCP
   direct-upload path call `ImageNormalizer.call(upload[:attachable])` in
   `Captures::Create#persist`. Putting the optimisation there means the stored blob is
   *always* the optimised master and the original is *never* persisted — for free, on both
   paths (web `attach(normalized)` stores the normalized bytes; MCP already purges the
   reserved blob via `upload[:blob]&.purge_later`).
   - Change: stop short-circuiting NATIVE unchanged. For **every decodable image**,
     `autorot → resize to MASTER_IMAGE_EDGE if larger → jpegsave(Q, strip: true)`.
   - Keep the up-front `ImageTooLarge` guard (reject > 25 MB before decode) and the
     `UnsupportedFormat` path unchanged.

2. **Master bound = 2048 px long edge, JPEG Q 85, EXIF stripped.**
   - 2048 keeps full-screen viewing crisp on retina/desktop (the review/detail surfaces),
     while recognition re-downscales 2048→1536 with negligible loss.
   - JPEG for all masters: capture photos are photographic; JPEG is smallest and
     universally displayable, and unifies the pipeline to one content type.
   - `strip: true` removes EXIF — a **privacy win** (phone photos carry GPS). `autorot`
     **before** strip bakes orientation so the image stays upright.
   - Constants live on `ImageNormalizer`: `MASTER_IMAGE_EDGE = 2048`, `JPEG_QUALITY = 85`
     (align the existing transcode quality to this).

3. **Serve named variants, not the master.** Define variants on the `Media` attachment and
   pick one per surface:
   - `:thumb` `resize_to_limit: [400, 400]` → gallery grid tiles + the capture session
     panel preview (small, `object-cover`).
   - `:detail` `resize_to_limit: [1600, 1600]` → item detail, review photo, recovery
     (full-width viewers).
   - Variants generate lazily on first request and cache in storage; each is tiny.

4. **Backfill via a tenancy-aware rake task, not a migration.** Reprocessing blobs is data
   work, not schema work — keep it out of `db:migrate`. The task iterates the
   `Organization` registry and `Apartment::Tenant.switch` into each schema (Media is
   tenant-scoped; blobs are shared `public`). Run it post-deploy with
   `kamal app exec --reuse 'bin/rails images:optimize'`. Idempotent + batched + re-runnable.

5. **Idempotency + reporting columns on `media`.** Add `optimized_at:datetime` (skip
   already-optimised rows; stamp new uploads) and `original_byte_size:bigint` (records the
   pre-optimisation size so the task can report total **MB reclaimed** — the "X MB" the
   prompt asks about). These are tenant-table columns; the migration runs per tenant via
   the deploy entrypoint (`db:prepare && db:migrate`; Apartment enhances `db:migrate`).

## Implementation blueprint (pseudocode + real anchors)

### A. `app/services/image_normalizer.rb` — optimise on the way in
```ruby
MASTER_IMAGE_EDGE = 2048
JPEG_QUALITY = 85   # was 88; align master + transcode

def call
  raise ImageTooLarge if reported_byte_size > Media::MAX_IMAGE_BYTES
  type = Marcel::MimeType.for(StringIO.new(bytes))
  return optimize(type) if NATIVE.include?(type) || TRANSCODABLE.include?(type)
  raise UnsupportedFormat, "Unsupported image format: #{type}"
end

# Replaces both the old pass-through and #transcode: always decode → autorot →
# downscale-if-larger → flatten-on-white (drop alpha) → JPEG. Always returns the
# attachable hash so Active Storage re-identifies the type from the bytes.
def optimize(type)
  require "vips"
  img = Vips::Image.new_from_buffer(bytes, "", access: :sequential).autorot
  scale = MASTER_IMAGE_EDGE.to_f / [img.width, img.height].max
  img = img.resize(scale) if scale < 1.0
  img = img.flatten(background: 255) if img.has_alpha?   # PNG transparency → white
  jpeg = img.jpegsave_buffer(Q: JPEG_QUALITY, strip: true)
  { io: StringIO.new(jpeg), filename: "#{File.basename(filename, ".*")}.jpg",
    content_type: "image/jpeg" }
rescue Vips::Error
  raise UnsupportedFormat, "Could not decode #{type} image"
end
```
*Mirror the existing `transcode` structure and its `rescue Vips::Error` → `UnsupportedFormat`
contract. Update the class doc comment (it currently claims natives are stored unchanged and
"the 5 display surfaces serve the original blob").*

### B. `app/models/media.rb` — named variants + stamp columns
```ruby
has_one_attached :image do |attachable|
  attachable.variant :thumb,  resize_to_limit: [400, 400]
  attachable.variant :detail, resize_to_limit: [1600, 1600]
end
```
(No behavioural change to validations; `SUPPORTED_IMAGE_TYPES` stays as the storage
backstop — the optimiser always emits `image/jpeg`.)

### C. Display surfaces — swap blob → variant (5 files)
Replace `rails_storage_proxy_path(media.image)` with the right variant:
- `app/views/boxes/gallery.rb:114` → `media.image.variant(:thumb)`  *(keep `loading: "lazy"`)*
- `app/views/captures/session_panel.rb:102` → `media.image.variant(:thumb)`
- `app/views/items/show.rb:82` → `@item.source_media.image.variant(:detail)`
- `app/views/reviews/photo.rb:56` → `@media.image.variant(:detail)`
- `app/views/recoveries/show.rb:44` → `@media.image.variant(:detail)`

### D. `lib/tasks/images.rake` — backfill (tenancy-aware, idempotent)
```ruby
namespace :images do
  desc "Downscale + recompress existing media blobs; reclaim storage"
  task optimize: :environment do
    reclaimed = 0
    Organization.find_each do |org|
      Apartment::Tenant.switch(org.slug) do
        Media.where(optimized_at: nil).find_each do |m|
          next unless m.image.attached?
          old = m.image.blob
          normalized = ImageNormalizer.call(            # reuse the same optimiser
            io: StringIO.new(old.download), filename: old.filename.to_s)
          m.image.attach(normalized)                    # new blob
          m.update!(optimized_at: Time.current, original_byte_size: old.byte_size)
          reclaimed += old.byte_size - m.image.blob.byte_size
          old.purge_later                               # reclaim storage
        rescue ImageNormalizer::UnsupportedFormat, ImageNormalizer::ImageTooLarge => e
          warn "skip media #{m.id}: #{e.class}"
        end
      end
    end
    puts "Reclaimed ~#{ActiveSupport::NumberHelper.number_to_human_size(reclaimed)}"
  end
end
```
*Stamp `optimized_at` on new uploads too — set it in `Captures::Create#attach_media` so
freshly-captured media is never re-touched by the backfill.*

### E. Migration
`add_column :media, :optimized_at, :datetime` and `:original_byte_size, :bigint`. Then
`bin/rails db:migrate` and commit the regenerated `db/structure.sql` (schema_format :sql).

## Gotchas / risks (read before coding)

1. **Per-tenant backfill.** Media is tenant-scoped — the task *must* `Apartment::Tenant.switch`
   per `Organization`; iterating only `public` finds zero media. (Blobs are shared `public`,
   so `purge_later` works globally.)
2. **Large-fixture testing.** The committed `sample_image.png` is tiny. Build a > 2048 px
   image in-spec with vips and **skip when vips can't decode** (reuse the spec's existing
   `require_decode!` pattern) rather than committing a multi-MB binary.
3. **PNG transparency → JPEG** flattens alpha; `flatten(background: 255)` avoids a black
   background. Acceptable for capture photos (no alpha needed).
4. **`autorot` before `strip`.** Bake EXIF orientation first, then strip metadata, or
   rotated phone photos display sideways. (Existing `transcode`/`downscale_jpeg` already do
   this — follow it.)
5. **Variants need libvips** (present in app + CI). Variant processor is the Rails-8 default
   `:vips` (no explicit config) — leave it.
6. **Lazy variant generation** makes the *first* request for each variant slower (it
   processes + caches). Acceptable; do not pre-warm (YAGNI).
7. **`structure.sql` + per-tenant migration** trips the `RailsSchemaUpToDate` overcommit
   hook if the dump isn't committed; the column migration runs across tenants via the deploy
   entrypoint (`db:prepare && db:migrate`) — Apartment enhances only `db:migrate`.
8. **Don't double-encode.** The optimiser runs once per upload; the backfill guards on
   `optimized_at` — so an image is JPEG-encoded at most once after this phase (avoids
   generational quality loss). Keep Q at 85 to stay visually lossless.
9. **`rails_storage_proxy_path` accepts a variant** — pass `media.image.variant(:thumb)`
   directly; in Phlex that's `view_context.rails_storage_proxy_path(...)`.
