Here's the same retrospective for the RBS + Steep adoption (#515→#526, v0.72.0–v0.76.0 — six PRs from the actions layer out to the Phlex views, ~1900 methods, zero unannotated defs repo-wide). Sources: the adoption memory, doc/project/type-checking.md, and the six PR bodies.

Genuine app bugs the checker caught

The rollout found five concrete runtime defects, all documented in the PR bodies (the memory tallies "six genuine bugs caught total" — the sixth appears to be the cross-file contract violation in the #520 round that only the whole-target verification pass caught after the scoped runs missed it):

1. A mixed String/Symbol hash key — caught before a single annotation was written. From PR #516: "Steep's literal-type inference found a mixed String/Symbol key hash in Moves::SetRecognitionProvider#persist before any annotation was written — normalized to a symbol key." The checker paid for itself on day one, on unannotated code.

2. A nil-unsafe rescue in account deletion. From PR #520: "Steep flagged Accounts::Delete#capture_attachment_ids — its broad best-effort rescue can technically fire before the accumulator local assigns, so the declared Array contract was nil-unsafe. The rescue now returns ids \|\| []."

3–5. Three live nil blind spots in models. From PR #522: "Box#volume_cm3 (equivalence against missing_dimensions? proven for all 7 callers), Item#image_generating?, RecognitionSuggestion#confidence_percent — each guarded a nullable attribute with one read and used a second read Steep correctly refused to narrow." Steep's refusal to narrow across two separate AR attribute reads looked pedantic but was right every time.

Notably, the controllers (#524) and views (#526) rounds each found zero runtime bugs — "the layer is thin by convention — validation lives in the actions," which is itself a validation of the actions-layer architecture.

Tooling/process bugs found along the way

- Steep 2.0's hang signature is a deadlock, not slowness: "steep check processes alive at 0% CPU for hours = master-thread crash → worker IPC deadlock." Two causes: the default daemon mode (hence the mandatory --no-daemon) and two Steepfile targets covering one directory in inline mode ("Source already exists").
- A silently-degraded subtree looks like success. One unresolvable constant in a class's ancestry (ActionPolicy::Controller) quietly disabled checking for the whole controller subtree — "a suspiciously-quiet baseline is a smell, not a win."
- Fan-out agents lie by omission. An annotation agent "reported 9/9 methods done but missed one (Boxes::SuggestDescription#clamp); the coverage spec caught it immediately. Mechanical claims by fan-out agents need a mechanical verifier, not report-trust." Same lesson from the views round: path-scoped steep check on the component tree can "vacuously check zero files and print 'No type error detected'" — whole-project runs only.
- The CI freshness gate itself had three blind spots (PR #522, one review cycle): environment-dependent generated paths, git diff --exit-code being blind to untracked new files (fixed with git add -N), and stale orphan files surviving regeneration (fixed with rm -rf before regenerating). Lesson recorded: "test all four drift directions before shipping: changed, new-untracked, deleted-stale, environment-dependent."
- The architecture research was almost wrong at its foundation: two of three architect agents disagreed on whether the rbs-inline preprocessor gem was still needed with Steep ≥ 2.0 (it isn't — Steep reads #:/@rbs natively). "Verify the pivotal tool capability against its CHANGELOG/source directly before choosing an architecture."

Architectural improvements

1. The third rail of the standards ladder — contracts, merge-blocking. Steep now complements the Move/* cops + fitness tests (vertical/layers) and Packwerk (horizontal/domains): every layer — actions, models, controllers, Phlex views — is type-checked in the CI lint job and an overcommit pre-commit hook.

2. Inline annotations with nothing to drift. "There is no rbs-inline preprocessor and no generated .rbs tree: types live next to the code they describe, so there is nothing to drift." And it's cheap: ~6 s whole-project, no DB, no Rails boot.

3. Real types where they're mechanically derivable. Schema-derived model signatures (sig/rbs_rails/, CI-freshness-enforced — "the model-signature analogue of RailsSchemaUpToDate") and typed route helpers generated under RAILS_ENV=test discipline, so "a renamed route is a NoMethod error at every stale call site." The Phlex tag DSL is covered by sig/phlex.rbs, "100% GENERATED by introspecting the installed gem's element registries" (115 HTML + 64 SVG tags) — regenerable, never hand-drifted.

4. A coverage ratchet on top of the checker. spec/architecture/type_annotations_spec.rb asserts every def in scope carries an annotation, because "Steep alone passes unannotated methods silently as (?) -> untyped" — the same fitness-test pattern that keeps the cops honest.

5. Honest, documented limits instead of overselling. The doc's "What the checker actually catches" section states the structural gaps plainly: do-notation's yield unwrap is untyped by construction — "each rail's shape is checked, the coupling between rails is not" — and cross-model mix-ups wait on #527 (tightening untyped domain params to real model types). Shims are deliberately minimal with deletion triggers, two of which have already fired (sig/active_support.rbs and sig/search_reindexing.rbs were deleted when better sources took over).

6. Growth by documented trigger, not speculation — a roadmap table mapping events (new pack, migration, community sigs catching up, inline def self. support landing) to exact actions, mirroring how the Packwerk migration was staged.

The full convention, shim table, and gotcha reference live in doc/project/type-checking.md.
